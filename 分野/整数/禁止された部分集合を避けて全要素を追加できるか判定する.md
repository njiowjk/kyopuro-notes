# 禁止された部分集合を避けて全要素を追加できるか判定する

## やりたいこと

空集合から未使用の要素を1個ずつ追加し、許可された部分集合だけを経由して全体集合へ到達できるか判定する。要素数が小さく、遷移先の可否と次の選択肢が現在の集合で決まる場合に使う。

## 基本的な考え方

追加済みの要素集合を `mask` で表す。次に選べる要素と遷移先の可否が現在の集合で決まるので、「全体集合に到達できるか」を集合ごとにメモ化する。

## 実装（C++）

`abc415_c` の形式でテストケース数と、各ケースの `N` および非空集合の禁止フラグを読む。照合した ADT 版の Python 実装と同じメモ化 DFS を使い、キャッシュをマスクで添字付けした配列に置き換える。

```cpp
#include <iostream>
#include <string>
#include <vector>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int tests;
    cin >> tests;
    for (int test = 0; test < tests; ++test) {
        int n;
        string forbidden;
        cin >> n >> forbidden;

        const unsigned states = 1u << n;
        const unsigned full = states - 1;
        vector<signed char> memo(states, -1);
        memo[full] = 1;
        auto reachable = [&](auto&& self, unsigned mask) -> bool {
            auto& result = memo[mask];
            if (result != -1) return result == 1;

            for (int i = 0; i < n; ++i) {
                const unsigned bit = 1u << i;
                if (mask & bit) continue;
                const unsigned next = mask | bit;
                if (forbidden[next - 1] == '0' && self(self, next)) {
                    result = 1;
                    return true;
                }
            }
            result = 0;
            return false;
        };
        cout << (reachable(reachable, 0) ? "Yes" : "No") << '\n';
    }
}
```

## 実装の要点

- `memo[mask]` は未計算 `-1`、到達不能 `0`、到達可能 `1` のいずれかを保持する。全体集合まで進めた状態を成功として初期化し、探索は空集合から始める。
- 未使用のビット1個を加えた `next` が許可され、その先に成功する経路があれば現在も成功。それ以外は失敗と記録する。全体集合に入る遷移も禁止状態の判定を通る。
- 追加のたびにビットの数が1増えるため循環がなく、異なる順で到達した同じ集合の結果を再利用できる。

## 計算量・注意点

各ケースの時間 O(N 2^N)、追加メモリ O(2^N)、再帰の深さ O(N)。入力に空集合のフラグはないので、安全な初期状態として扱う。全体集合を含めて遷移先の可否を先に調べる。ケースごとにキャッシュを初期化し、`1u << n` が有効で全状態を確保できる小さな `N` に使う。
