# C - Dislike Foods

## 問題概要

`N` 種類の食材と `M` 個の料理を読み、各料理に含まれる `K_i` 種類の食材が与えられる。克服順 `B` は食材番号の順列。各日の克服直後に、苦手な食材を含まない料理の総数を1行ずつ出力する。`1 <= N,M <= 3×10^5`、`ΣK_i <= 3×10^5`。各料理の食材は相異なり、`K_i >= 1`。

## 解法の概要

食材と料理を二部グラフと考え、食材からそれを使う料理を引ける隣接リストを作る。料理ごとの苦手な食材数を `K_i` で初期化し、その日の食材が入る料理だけ1減らす。残数は常にその時点の苦手な食材数であり、初めて0になった料理を累計に足す。各食材は一度だけ克服され、各辺は一度だけ処理する。`E=ΣK_i` とすると、ハッシュ集合を用いる実装の期待時間は O(N+M+E)、追加メモリは O(N+M+E)。

主分類は [グラフ](../../分野/グラフ/グラフ.md)。

## 問題固有の実装ポイント

- 料理番号と食材番号は別々の添字として管理する。番号を0始まりに変換しても、食材の個数 `K_i` は元の値を使う。
- ある食材がどの料理にも含まれない日は累計が変わらない。複数の料理の残数が同じ日に0になればすべて足す。最終日の出力は `M`。

## 自作コード

Inbox で照合したローカルソースを解析した。提出との対応とジャッジ結果は未確認。

Python の `defaultdict(set)` で食材から料理番号の集合を引き、料理ごとの残数を配列で持つ。入力行の全数値を1減らしているため、食材数を配列へ入れる際は1を足して戻す。料理内に同じ食材が重複しないので、C++ では食材ごとの `vector` でも処理できる。

全2サンプルと、各日に全料理を再判定する素朴な実装との照合を行い、使われない食材や同日に複数の料理が追加される場合も確認した。
