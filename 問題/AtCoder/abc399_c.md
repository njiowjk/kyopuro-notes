# C - Make it Forest

## 問題概要

`N M` と `M` 本の単純無向辺 `u_i v_i` を読む。閉路のないグラフ（森）にするための最小削除数を出力する。`1 <= N <= 2×10^5`、`0 <= M <= min(N(N-1)/2, 2×10^5)`、`1 <= u_i < v_i <= N`。自己ループと多重辺のないことが保証される。

## 解法の概要

Union-Find で採用済みの辺による連結成分を管理する。異なる成分を結ぶ辺だけを採用すれば閉路はできない。採用しなかった辺の両端は既に連結しているため、全辺の処理後に元のグラフと同じ連結成分が得られる。元の成分数を `C` とすると、採用できたのは `N-C` 本。各成分の頂点数を `k` とするとその中に残せる無閉路の辺は高々 `k-1` 本なので、最小削除数は `M-N+C`。

経路圧縮とサイズによる併合を用いて時間 O(N + M α(N))、追加メモリ O(N)。保存済みコードは辺を逐次処理する。

主分類は [グラフ](../../分野/グラフ/グラフ.md)。

## 問題固有の実装ポイント

- 1始まりの頂点番号を0始まりに直す。孤立頂点も Union-Find の初期成分に含める。
- `M=0` や入力が既に森なら削除数は0。自己ループと多重辺の検出だけでは、三角形などの閉路を扱えない。
- 既存のC++版 Union-Find では、`uf.unite(u, v)` が `true` を返すたびに、`M` から始めた答えを1減らせば同じ処理になる。

## 自作コード

Inbox で照合した Python のローカルスナップショット（取得元 `atc-rs-local`）を参照した。提出との対応とジャッジ結果は未確認。

`atcoder.dsu.DSU` を使う。削除候補数 `ans` を `m` で初期化し、`not uf.same(u,v)` の場合だけ `merge` して `ans` を1減らす。既に同一成分なら何も更新しない。連結判定と併合の既存テンプレートに、採用辺数の集計を1行加えれば再利用できる。

検証では `ac-library-python` を一時環境に用意し、全3サンプルと、孤立頂点と複数の閉路を含む182グラフを隣接リストの探索で得た成分数と照合した。
