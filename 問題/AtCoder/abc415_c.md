# C - Mixture

## 問題概要

`T` ケースそれぞれで、薬品の種類数 `N` と長さ `2^N-1` の二値文字列 `S` を読む。空の瓶に1種類ずつ加え、経由する全状態が安全なまま全種類を混ぜられるかを `Yes` / `No` で答える。`1 <= T <= 40000`、`1 <= N <= 18`、各ケースの `|S|` の総和は `5×10^5` 以下。

## 解法の概要

既に入れた薬品の集合をビットマスク `used` で表し、空集合 `0` からメモ化 DFS を行う。`dfs(used)` は、現在の集合から安全な状態だけを経由して全種を入れられるかを返す。全ビットが立っていれば成功。未使用の1ビットを足した `next` が安全で、その先が成功する遷移が一つでもあれば現在も成功する。

続きの選択肢と安全性は現在の集合で決まるので、異なる順序で到達した同じ集合の結果を再利用できる。各遷移で集合の要素数が1増えるため循環はない。各ケースの時間は最悪 O(N 2^N)、入力とメモの領域は O(2^N)、再帰の深さは O(N)。主分類は [整数](../../分野/整数/整数.md)。

## 問題固有の実装ポイント

- `S` に空集合は含まれない。空集合は安全として開始し、非空マスク `next` の安全性は0始まりの `S[next-1] == '0'` で調べる。
- 全種類が入ったマスクも遷移先として安全性を確かめてから到達する。`N=1` では唯一の非空状態が安全かどうかで決まる。
- ケースごとにメモを作り直す。種類数が同じケースでも禁止状態は変わる。

## 自作コード

ADT 側のローカルメタデータで同じ task ID の E 枠に対応する Python 実装を照合した。`functools.cache` をケースごとの再帰関数に付け、使用済みマスクをキーにする。使っていない薬品を足せるかを順に試し、成功する枝が見つかれば探索を打ち切る。提出との対応とジャッジ結果は未確認。

公式サンプルの5ケース、`N <= 3` の禁止状態の全138通り、短い入力64件を確認した。短い入力の期待値は追加順の全列挙で求めた。`N=18` の全状態が安全な場合、最終状態が禁止の場合、可能な追加順が一つの場合と、`T=40000`、`|S|` 総和 `5×10^5` でも期待値に一致した。
