# C - Flapping Takahashi

## 問題概要

`T` ケースを読み、各ケースで初期高度 `H` と `N` 個の目標 `t_i l_i u_i` が与えられる。時刻 `t_i` に高度が閉区間 `[l_i,u_i]` に入るよう、常に正の高度を保って毎秒高々1だけ高度を変えられるかを `Yes` / `No` で答える。時刻は狭義昇順、時刻と高度の入力値は1以上 `10^9` 以下。`1 <= T, N <= 10^5` で、全ケースの `N` の総和は `10^5` 以下。

## 解法の概要

時刻0で到達可能な高度は `[H,H]`。直前の全目標を満たす高度が `[low,high]` なら、時刻差 `dt` だけ進んだあとに到達できる高度は `[low-dt,high+dt]` を正の範囲に制限したもの。その時刻の目標 `[l_i,u_i]` と交差させ、下端が上端を超えたら失敗する。

交差内のどの高度にも、直前の区間内に距離 `dt` 以下の出発点がある。正の出発点と到着点を直線で結べば、途中も正で速度制限を満たす。最後の目標を満たした後は同じ高度にとどまれる。各ケースで時間 O(N)、追加メモリ O(1)。

主分類は [整数](../../分野/整数/整数.md)。この問題は整数の境界値で到達範囲を管理できる。

## 問題固有の実装ポイント

- `l_i >= 1` なので、目標区間との交差を取れば到着点は必ず正になる。
- 下端と上端が等しい場合も到達できる。変化量に使うのは時刻の累計ではなく、直前の目標からの経過時間。
- 一度でも交差が空になれば、その後の目標が単独で達成可能でも答えは `No`。残りの目標行を読み、次のテストケースとの境界を保つ。

## 自作コード

Inbox で照合した Python のローカルスナップショットを参照した。提出との対応とジャッジ結果は未確認。

`mini`、`maxi` を `H`、`cur` を0で初期化する。時刻差だけ上下に区間を広げ、下端を0以上にしたうえで目標区間との重なりを判定する。`f` は一度 `False` になると戻らない。C++17 案では `l_i >= 1` を使って下端の0への補正を省き、失敗後は目標行の読み取りだけを続ける。

公式サンプルに加え、区間が一点で接するケース、途中で矛盾するケース、大きな時刻差、短い範囲で到達可能な整数高度を列挙するケースを確認した。
