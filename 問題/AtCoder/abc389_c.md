# C - Snake Queue

## 解法の概要

空の列に対し、長さ `l` のヘビを末尾に追加する `1 l`、先頭を削除する `2`、先頭から `k` 番目の頭の座標を出力する `3 k` を順に処理する。先頭を削除したら、残りの座標は削除した長さだけ減る。`1 <= Q <= 3×10^5`、`1 <= l <= 10^9`。削除する先頭と照会する `k` 番目は存在する。

追加順の長さの累積和を `P` とし、`P[i]` を最初の `i` 匹の長さの合計とする。削除済みの匹数を `head` とすると、現在の先頭から `k` 番目の頭までには区間 `[head, head+k-1)` の長さがある。答えは `P[head+k-1]-P[head]`。追加で累積和を1つ延ばし、削除は `head` を1増やすだけで済む。

全体時間 O(Q)、追加メモリ O(Q)。動的配列への末尾追加は償却 O(1)、削除と照会は各 O(1)。主分類は [配列](../../分野/配列/配列.md)。

## 問題固有の実装ポイント

- `k = 1` では差が0。列が空になって再追加された場合も、新しい先頭の累積和が基準になるので、座標は0になる。
- 歴代の長さの合計は最大 `3×10^14`。C++ では累積和を `long long` にする。タイプ3がなければ出力は空。

## 自作コード

Inbox で照合した Python のローカルスナップショットを参照した。提出との対応とジャッジ結果は未確認。

追加順の頭の累積座標を `que`、各長さを `leng` に保持する。`last` は追加した長さの総和、`diss_p` と `diss` は削除済みの匹数と長さの総和。照会時は `que[k+diss_p-1] - diss` を出力する。`P[0] = 0` を含む累積和を伸ばす実装なら、削除済みの長さの総和は `P[head]` から取れる。

公式サンプル3件、短い操作列での逐次シミュレーションとの照合、空になった列への再追加、30万クエリで32ビットを超える座標を確認した。
