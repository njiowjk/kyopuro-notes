# C - Sigma Problem

## 問題概要

`N` と正整数列 `A_1 ... A_N` を読む。全添字ペア `i < j` について `(A_i + A_j) % 10^8` を求め、その総和を出力する。`2 <= N <= 3×10^5`、`1 <= A_i < 10^8`。

## 解法の概要

`M = 10^8`、`D` を和が `M` 以上のペア数とする。各ペアの和は `2*M` 未満なので、余りを取る操作では各ペアから高々1回だけ `M` が引かれる。剰余を取る前の合計では各要素が他の `N-1` 要素と組むので、答えは `(N-1)*sum(A) - M*D`。

ペアの条件は値の組だけで決まるため、整列しても数は保存される。`i` ごとに `j > i` の範囲で `A[j] >= M-A[i]` の最初の位置を二分探索し、それ以降の要素数を `D` に足す。時間 O(N log N)、配列以外には二分探索・集計用の定数個の変数を使う。Python の `list.sort()` の作業領域は最悪 O(N)。

主分類は [配列](../../分野/配列/配列.md)。

## 問題固有の実装ポイント

- `bisect_left` を使うため、和がちょうど `M` のペアも補正対象。元コードの「超える」というコメントに対し、実際の比較は「以上」。
- 探索の左端は `i+1`。重複値は別の添字として数え、自分自身や同じペアの逆順は含めない。
- 求めるのは剰余の総和。最後にもう一度 `% M` は適用しない。C++移植ではペア数、総和、`M*D` に64ビット整数を使う。

## 自作コード

Inbox で照合した Python のローカルスナップショット（取得元 `atc-rs-local`）を参照した。提出との対応とジャッジ結果は未確認。

`a.sort()` の後に `bisect_left(a, 10**8-a[i], i+1)` を呼び、位置を `n` から引いた数を `did` に足す。別のループで `a[i]*(n-1)` を積み上げてから `did*10**8` を引く。`sortedcontainers` と `more_itertools` をインポートするが、集計には標準ライブラリの `bisect_left` だけを使う。これらの外部ライブラリがない環境では開始時のインポートで失敗する。

検証では外部依存を一時環境に用意し、全2サンプル、和が `M` のケースを含む短列の全ペア計算、30万要素の上限寄りのケースを確認した。
