# C - Large Queue

## 解法の概要

空の整数列に対し、値 `x` を末尾に `c` 個追加する `1 c x` と、先頭の `k` 個を削除して合計を出力する `2 k` を順に処理する。`1 <= Q <= 2×10^5`、`1 <= c,x <= 10^9`、`1 <= k <= 10^9`。削除個数はその時点の列の長さ以下。

追加1回を「残個数と値」の1組で持つ。削除時は先頭の組から必要個数と残個数の小さい方だけ取り、その個数と値の積を足す。取り切った組を飛ばし、一部だけ取った組は残個数を更新して先頭に残す。先頭から組を展開した列が実際の残りと一致するため、削除区間の総和を得られる。

先頭を通過できるのは各組1回で、部分削除も各削除クエリにつき高々1回。全体時間 O(Q)、組を保持する追加メモリ O(Q)。主分類は [配列](../../分野/配列/配列.md)。

## 問題固有の実装ポイント

- 同じ値を連続で追加しても、クエリ単位で別々の組に保持してよい。組数は追加クエリ数以下。
- ちょうど組の最後まで取り出したときは次の組を先頭にする。列が空になったあとも、次の追加で再開できる。
- 削除1回の答えは最大 `10^18` なので、C++ では個数と値を掛ける時点から `long long` を使う。

## 自作コード

Inbox で照合した Python のローカルスナップショットを参照した。提出との対応とジャッジ結果は未確認。

組を配列に追加し、`left` が現在の先頭の組を指す。残個数が必要数より大きければ先頭の組だけを更新する。等しければ合計に足して `left` を進め、足りなければ同じ処理の後に必要数を減らして次の組を見る。

公式サンプル3件、短い操作列での展開したキューとの照合、部分削除と空列への再追加、`10^18` の答え、20万クエリで多数の組を一度に削除するケースを確認した。
