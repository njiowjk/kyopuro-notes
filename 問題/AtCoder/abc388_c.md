# C - Various Kagamimochi

## 問題概要

`N` と餅の大きさ `A_1 ... A_N` を読む。異なる2個の餅を選び、小さい方の大きさの2倍が大きい方以下となる選び方を数える。同じ大きさでも添字の異なる餅は区別する。`2 <= N <= 5×10^5`、`1 <= A_i <= 10^9`。配列は昇順（広義単調増加）で与えられる。

## 解法の概要

小さい側の添字 `left` を固定すると、条件 `2*A[left] <= A[j]` を満たす `j` は最初に条件を満たす `right` から末尾までの接尾区間。各 `left` で `N-right` 組を足す。`A[left]` が増えるにつれて閾値も下がらないので、`right` は前回位置から右へだけ進めればよい。各ポインタは高々 `N` 回進み、時間 O(N)、入力配列を除く追加メモリ O(1)。

主分類は [配列](../../分野/配列/配列.md)。

## 問題固有の実装ポイント

- 全値が正なので `2*A[left] > A[left]`。`right` に `left+1` の下限を明示しなくても、自分自身や手前の餅はカウントされない。
- 内側のループが止まるのは `A[right] >= 2*A[left]` または `right == N`。等号のペアも加える。
- `right == N` なら以後の閾値でもペアが見つからない。C++では合計を `long long` にし、倍を取る前に型を広げる。

## 自作コード

Inbox で照合した Python のローカルスナップショット（取得元 `atc-rs-local`）を参照した。提出との対応とジャッジ結果は未確認。

`left = right = 0` から始め、内側の `while` で条件を満たさない右側候補を飛ばす。`ans += n-right` のあとに `left` を1進め、右側の候補が尽きたら外側の走査を終える。入力の整列済みという保証を利用し、境界を2本のポインタで求める。各ペアは小さい側の添字で一度だけ加算する。

検証では全3サンプル、短い昇順列の全ペア列挙、50万要素で答えが 62,500,000,000 になるケースを確認した。
