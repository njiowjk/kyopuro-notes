# C - Airport Code

## 問題概要

長さ3以上 `10^5` 以下の英小文字列 `S` と、英大文字3文字の `T` を1行ずつ読む。`S` から順序を保って3文字を選び大文字化するか、2文字を選んで大文字化し末尾に `X` を付けて、`T` を作れるかを判定する。

## 解法の概要

`S` を大文字化し、末尾に `X` を1個追加した列に `T` が部分列として現れるか判定する。追加文字を使うときは位置の順序から `T` の3文字目にしかならず、使わないときは元の `S` だけで3文字を選んでいる。各文字は左から最も早く一致する位置で確定できる。早い位置に置くほど、残りの文字の検索に使える範囲が広くなるため。

時間 O(|S|)、保存済み実装は大文字のリストを生成するため追加メモリ O(|S|)。部分列の判定自体が保持する状態は一致済み文字数1個。

主分類は [文字列](../../分野/文字列/文字列.md)。

## 問題固有の実装ポイント

- 追加した `X` は1個だけなので、`T` が `AXX` なら2文字目に使う `X` は元の `S` に必要。
- 同じ文字を連続で探すときも、`S` の同じ1文字を2回使えない。
- 3文字目が一致したら直ちに終了するため、次の周回で `t[3]` を参照しない。

## 自作コード

Inbox で照合した Python のローカルスナップショット（取得元 `atc-rs-local`）を参照した。提出との対応とジャッジ結果は未確認。

`upper()` で大文字にした `S` をリストへ変換して `X` を追加する。`cnt` は何文字確定したかを表し、現在の文字が `t[cnt]` と等しいときだけ増える。`cnt == 3` で `Yes` を出してループを抜け、完走時の `for … else` で `No` を出す。

検証では全3サンプル、短い文字列200組の部分列列挙、末尾への `X` の補完と元の `X` を併用するケースを確認した。

## 公式解法・参考資料

- 3文字の部分列と「2文字＋末尾の `X`」という二通りの条件を確認した。[AtCoder 公式問題文](https://atcoder.jp/contests/abc349/tasks/abc349_c)
- 公式解説は `T` の末尾が `X` なら探索対象を先頭2文字に切り替える。保存済みコードでは走査対象に `X` を加えて判定を共通化している。両者の部分列判定には同じ貪欲法を使う。[AtCoder 公式解説](https://atcoder.jp/contests/abc349/editorial/9779)
