# C - Count ABC Again

## 問題概要

`N Q`、英大文字列 `S`、続けて `Q` 行の `X_i C_i` を読む。各クエリで `S` の `X_i` 文字目を `C_i` に置換し、連続する `ABC` の出現数を出力する。`3 <= N <= 2×10^5`、`1 <= Q <= 2×10^5`、`1 <= X_i <= N`、`C_i` は英大文字。

## 解法の概要

出現数を初回の全走査で数え、以後は変更前後の差分で更新する。0-indexed の位置 `x` を含む長さ3の窓の開始位置は `x-2` から `x` まで。その範囲を有効な開始位置 `[0, N-3]` に絞れば、変化し得る窓をすべて拾える。更新ごとに最大3窓だけ比較するので、時間 O(N + Q)、文字列を可変リストとして保持するメモリが O(N)、更新時の追加メモリは O(1)。

主分類は [文字列](../../分野/文字列/文字列.md)。

## 問題固有の実装ポイント

- `X_i` を1回だけ0-indexedに直す。Python の `range` に渡す上限は排他的なので `min(n-2, x+1)`。
- 同じ文字への置換でも現在の出現数を出力する。
- 一致判定に必要なのは長さ3の文字だけ。一般の長さ `L` では候補窓が最大 `L` 個になり、窓を直接比較する更新の最悪時間は O(L²)。

## 自作コード

Inbox で照合した Python のローカルスナップショット（取得元 `atc-rs-local`）を参照した。提出との対応とジャッジ結果は未確認。

初期化では窓の右端 `i` を2から進めて `ans` を数える。更新では窓の左端を基準にし、`cnt` を変更前、`cnt_b` を変更後の一致数として `ans += cnt_b - cnt`。`s[x]` の代入を2回の走査の間に置くため、別の出現位置表を持たずに済む。

検証では全3サンプルと、先頭・末尾・同一文字への更新を含む100系列を全走査と照合した。
