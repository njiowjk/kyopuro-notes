# C - Sum = 0

## 問題概要

`N` 個の整数区間 `[L_i, R_i]` が与えられる。各区間から整数を1つずつ選び、総和が0になる列があれば `Yes` とその一例、なければ `No` を出力する。`1 <= N <= 2×10^5`、`-10^9 <= L_i <= R_i <= 10^9`。

## 解法の概要

まず全要素を下限に置き、`sum L_i <= 0 <= sum R_i` かを調べる。成立するなら不足分 `-sum L_i` を、各要素が増やせる幅 `R_i-L_i` の範囲で順に埋める。各幅の中のどの整数分でも加算でき、利用できる全幅の合計が不足分以上なので、残りは必ず0になる。

時間 O(N)、区間と構成結果を含めてメモリ O(N)。

主分類は [整数](../../分野/整数/整数.md)。

## 問題固有の実装ポイント

- 下限の総和または上限の総和が0の場合も構成可能。幅が0の要素はそのまま出力する。
- 判定だけでなく、範囲と総和をともに満たす列を出す。C++ では各値が32ビット内でも、総和と残量は `long long` で扱う。

## 自作コード

Python の照合済み実装は、下限の総和と上限の総和を集計し、下限の累積和の末尾から不足分を得る。残りを一度で埋められる要素があればそこで終了し、埋めきれない場合はその要素を上限まで増やす。判定を通った後は残量が非負なので、加算後の値が下限を下回る分岐には到達しない。 本人の提出との対応とジャッジ結果は未確認。

照合済み実装で公式サンプル全3件と、総和が上下限に一致するケース、構成できない範囲、32ビットを超える途中の総和を確認した。 構成した列は出力例との文字列比較ではなく、各要素の範囲と総和を検査した。
